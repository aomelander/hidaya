## Confirmed defects and corrections

- **Incorrect audio identity:** the resolver invented deterministic IDs for arbitrary verses and pointed them to the same sample translation. Unknown UUIDs also returned an English sample. A French tafsir catalog entry pointed to a translation member. Removed the unverified fallback catalog and fabricated records; missing database records now remain unavailable. Database metadata must match verse, language, stream type and the displayed translator/scholar. Public attribution is restricted to source/scholar fields.
- **Scholar mismatch:** continuous playback chose a scholar by array position. It now finds the requested scholar by name. Both players send displayed source identity with metadata requests. Multi-verse secondary audio is skipped until full-range recordings can be resolved, rather than reading only the first verse against combined text. Arabic Quran recitation remains available.
- **Unrequested speech:** both players could silently synthesize missing recordings. Removed that fallback from both playback components. Speech-generation services and `/api/tts` remain unchanged as requested.
- **Playback lifecycle:** inline range advancement/reset and looping conflicted; late secondary callbacks and timers could resume stale sessions. Fixed inline track progression and looping; cancel stale requests/listeners, remove delayed transitions, stop on language/source/filter changes and unmount, and use one playback owner across players. Secondary mute and speed now follow controls. Inline pause preserves position.
- **Language/provenance:** removed an English boundary-text fallback, restricted dynamic Arabic tafsir hydration to Arabic mode, require reviewed remote tafsir before presenting it as verified, and stopped promoting missing remote verification status to canonical. Synthesis instructions now name Swedish/French where selected. Personal synthesis is no longer written to the server reflection cache.
- **Highlighting:** existing highlights interpolate elapsed duration; there are no word timestamps. Both players now explicitly label this as approximate. This does not establish that a recording's transcript equals the displayed excerpt.
- **HTTP range:** added suffix/open-ended ranges, clamped end offsets, and 416 responses for malformed/unsatisfiable ranges. Cached recordings return the requested 206 byte slice too. Existing ZIP protections against full-archive downloads, invalid hosts, traversal and unsupported compression were retained.
- **Caching:** replaced old audio/shell/passage buckets to retire incorrect cached recordings and API responses. Audio saves reject opaque, partial, non-audio and oversized responses; serialize writes; enforce 20 MiB per recording and 50 MiB total with oldest-first eviction. Central-directory retained metadata has a 16 MiB serialized-size budget in addition to archive count limits; MP3 replacement byte accounting is corrected. Worker shell/passage caches use 2 MiB per entry and 10 MiB per bucket; local passage JSON is capped at 2 MiB. Dedicated metadata cache supports offline resolution, capped at 100 records of at most 8 KiB. Unrelated caches are preserved. Generic API responses, including admin responses, bypass shell caching.
- **Security/build:** admin ingestion GET/POST and paid diagnostic GET now fail closed unless a server-only `HIDAYA_ADMIN_TOKEN` matches a Bearer authorization header. Dev-server allowed hosts are restricted. A missing Gemini key no longer crashes guidance module import. Added a Node >=22.12 requirement and `.nvmrc`; the existing Node 22 installation builds successfully without dependency changes.
- **Accessibility/UX:** audio search has an accessible label and an explicit localized empty state; an empty search result no longer plays an unrelated fallback passage. Empty inline audio-addition controls are hidden.

- The original audit was local only. The user subsequently authorized release; see the addendum below.
- Exact audio/text equivalence, pronunciation, canonical attribution correctness, and real production database inventory were not verified by listening or querying production rows. Matching currently fails closed on exact attribution names; alternate naming in valid records may hide audio until a reviewed mapping is supplied.
- No timestamp data was found. Word highlighting remains approximate. Range secondary recordings are deliberately unavailable rather than falsely treated as complete.
- Native Safari/iOS seeking/autoplay, real audio decoding, cross-tab behavior without Web Locks, full offline reload after installation, and device quota failures still need real-device checks. Browser regression tests use mocked media.
- Newly versioned offline buckets require recordings to be downloaded again. Notes/bookmarks and other local user data are not deleted. Cache budgets are payload/serialized metadata budgets, not promises about total JavaScript heap overhead.
- Admin ingestion now requires configured server authorization. No token was created or exposed; the existing public modal does not supply one, so it cannot perform admin actions. An authenticated administration UI is a separate design task.
- `/api/tts` remains an unauthenticated paid-generation surface because audio generation was expressly excluded. Public guidance also invokes paid embedding/synthesis paths without durable per-user abuse controls. These risks were identified statically; neither was exercised. Addressing generation access and quota policy requires a separately scoped change.
- Historical source prose and fixture scholarly attribution have not received a full theological/source audit. Previously saved reflection-cache records were not deleted, consistent with leaving production data unchanged.
